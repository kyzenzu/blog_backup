### `fflush` —— 刷新缓冲区

##### 函数原型

```c
#include <stdio.h>

int fflush(FILE *stream);
```

##### 功能说明

将文件流 `stream` 的用户态缓冲区中尚未写入的数据**强制刷新**到底层内核（或磁盘）。

##### 返回值

- **成功**：返回 `0`。
- **失败**：返回 `EOF`（通常为 `-1`），并设置 `errno`。

##### 所需头文件

| 头文件               | 必要性   | 说明                                                  |
| -------------------- | -------- | ----------------------------------------------------- |
| `#include <stdio.h>` | **必须** | C 标准库规定 `fflush` 函数的声明位于 `<stdio.h>` 中。 |

##### 参数详解

| 参数     | 说明                                                         |
| -------- | ------------------------------------------------------------ |
| `stream` | 指向 `FILE` 结构的文件流指针。传入 `NULL` 表示刷新**所有**已打开的输出流。 |

##### 核心行为

- **输出流**（如 `stdout`、文件写流）：将缓冲区数据写入内核。
- **输入流**（如 `stdin`、文件读流）：行为未定义（不应在输入流上调用 `fflush`）。
- **`stream == NULL`**：刷新所有输出流。

##### 代码示例

```c
int main() {
    FILE* pFile = fopen("./test", "wb+");
    if (pFile != NULL) {
        struct Test data = {
            1000,
            "Tiger",
            28
        };
        // 写入 1 个元素，每个元素大小为 sizeof(Test)
        fwrite(&data, sizeof(struct Test), 1, pFile);

        // 强制刷新缓冲区，确保数据写入磁盘
        fflush(pFile);
        fclose(pFile);
    }
    return 0;
}
```

### 一、文件流状态检查

#### 1. `feof` —— 检查是否到达文件末尾

##### 函数原型
```c
#include <stdio.h>

int feof(FILE *stream);
```

##### 功能说明
检查文件流 `stream` 的 **EOF 标志位**是否被设置。该标志位由读取函数（如 `fgetc`、`fgets`、`fread`）在**尝试读取但读到 0 个字节**（即已到达文件末尾）时自动设置。

##### 返回值
- **EOF 标志位为 1**：返回非零值（真）。
- **EOF 标志位为 0**：返回 `0`（假）。

##### 所需头文件

| 头文件               | 必要性   | 说明                                                         |
| -------------------- | -------- | ------------------------------------------------------------ |
| `#include <stdio.h>` | **必须** | C 标准库规定 `feof`、`ferror`、`clearerr`、`rewind` 等文件流状态函数的声明位于 `<stdio.h>` 中。 |

##### ⚠️ 核心陷阱：`feof` 不会预判 EOF

`feof` **不是**判断“当前位置是否等于文件末尾”，而是判断“**是否已经尝试读取过文件末尾**”。

```c
// glibc 简化实现
int feof(FILE *stream) {
    return (stream->_flags & _IO_EOF_SEEN) != 0;  // 检查 EOF 标志位
}
```

- EOF 标志位**只有**在执行读取函数**失败**（读到 0 字节）时才会被设置。
- 即使文件读写位置恰好在文件末尾，只要还没执行过读取操作，`feof` 仍返回 `0`。

> 特别注意：`feof`直接返回**文件流内部的 `EOF` 标志位（`_IOEOF`）**的值，它并不会判断 `文件读写位置 == EOF`。而文件流内部的 `EOF` 标志位只有在执行文件读取函数（如`fgetc`、`fgets`）时读取到 `0` 个字节时才会设置。也就是说想用  `feof` 及时的判断是否读取到文件的 `EOF`位置是错误的。

##### ❌ 错误示例

```c
int main() {
    FILE* pFile = fopen("./test.txt", "r");
    if (pFile != NULL) {
        char buf[1024];
        while (!feof(pFile)) {           // ❌ 错误：最后一次循环时 EOF 标志未设置
            fgets(buf, 1024, pFile);
            printf(buf);                 // 最后一次会打印上一行的内容（多打印一行）
        }
        fclose(pFile);
    }
    return 0;
}
```

**问题原因**：

在读取文件内容的最后一行后，`fgets`并非读取了0个字节，所以`EOF` 标志位没有置`1`，虽然此时文件的读写位置恰好在`EOF`上，但只有多执行一次循环，`fgets`才会把**文件流内部的 `EOF` 标志位（`_IOEOF`）**的值设置为 `1`，而输出里多出来的正好是上一次循环 `buf` 里的内容（文件内容的最后一行）

##### ✅ 正确写法

```c
char buf[1024];
// 正确的做法：直接在读取函数返回 NULL/EOF 时跳出
while (fgets(buf, sizeof(buf), pFile) != NULL) {
    // 处理读到的有效数据
    printf("%s", buf);
}
// 循环结束后，此时才可以用 feof() 来判断是因为读完了还是因为出错
if (feof(pFile)) {
    printf("正常到达文件末尾\n");
} else if (ferror(pFile)) {
    printf("发生了读取错误\n");
}
```

#### 2. `ferror` —— 检查是否发生 I/O 错误

##### 函数原型
```c
#include <stdio.h>

int ferror(FILE *stream);
```

##### 功能说明
检查文件流 `stream` 的**错误标志位**是否被设置。该标志位由读写函数在执行过程中遇到**底层 I/O 错误**时自动设置。

##### 返回值
- **发生错误**：返回非零值（真）。
- **未发生错误**：返回 `0`（假）。

##### 所需头文件

| 头文件               | 必要性   | 说明                                                  |
| -------------------- | -------- | ----------------------------------------------------- |
| `#include <stdio.h>` | **必须** | C 标准库规定 `ferror` 函数的声明位于 `<stdio.h>` 中。 |

##### 源码实现（glibc）

```c
// 简化的底层逻辑
int ferror(FILE *stream) {
    return (stream->_flags & _IO_ERR_SEEN) != 0;  // 检查错误标志位
}
```

当底层系统调用（如 `read`、`write`）返回 `-1` 并设置 `errno` 时，标准库会执行类似 `stream->_flags |= _IO_ERR_SEEN;` 的操作，将标志位从 `0` 置为 `1`。

##### 触发场景（何时变为真？）

##### 代码示例

```c
int main() {
    FILE* pFile = open("./test.txt", "r"); // 只读方式打开文件
    fputc('a'); // 试图写入文件
    printf("ferror: %d\n", ferror(pFile)); // 输出 1
}
```

| 场景           | 具体表现                                                     |
| -------------- | ------------------------------------------------------------ |
| **磁盘已满**   | 写入时 `write` 返回 `-1`（`ENOSPC`），`fwrite` 失败，设置错误标志 |
| **设备断连**   | 读取已卸载网络驱动器或已弹出 USB 设备上的文件，底层返回 `-1`（`ENXIO` 或 `EIO`） |
| **权限变更**   | 打开时有读权限，读取过程中权限被收回，后续读取失败           |
| **管道破裂**   | 向没有读端的管道写入数据，`write` 返回 `-1`（`EPIPE`），触发错误标志 |
| **无效偏移量** | 在不可定位的设备（如终端、套接字）上调用 `fseek` 失败        |

> **特别提示**：到达文件末尾（EOF）**不属于** I/O 错误，`ferror()` 在读到文件尾时**始终返回 `0`（假）**。

### 二、清理函数

#### 1. `clearerr` —— 清除错误和 EOF 标志

##### 函数原型
```c
#include <stdio.h>

void clearerr(FILE *stream);
```

##### 功能说明
**同时清除**文件流 `stream` 的**错误标志位**（`_IO_ERR_SEEN`）和 **EOF 标志位**（`_IO_EOF_SEEN`），将它们重置为 `0`。

##### 返回值
无返回值（`void`）。

##### 所需头文件

| 头文件               | 必要性   | 说明                                                    |
| -------------------- | -------- | ------------------------------------------------------- |
| `#include <stdio.h>` | **必须** | C 标准库规定 `clearerr` 函数的声明位于 `<stdio.h>` 中。 |

##### 使用示例
```c
if (ferror(fp)) {
    printf("发生错误，正在清除标志...\n");
    clearerr(fp);  // 此时 ferror(fp) 恢复为 0
}
```

#### 2. `rewind` —— 重置读写位置并清除错误和 EOF 标志

##### 函数原型
```c
#include <stdio.h>

void rewind(FILE *stream);
```

##### 功能说明
将文件流 `stream` 的读写位置重置到文件**开头**，同时**清除**错误标志位和 EOF 标志位。

##### 返回值
无返回值（`void`）。

##### 所需头文件

| 头文件               | 必要性   | 说明                                                  |
| -------------------- | -------- | ----------------------------------------------------- |
| `#include <stdio.h>` | **必须** | C 标准库规定 `rewind` 函数的声明位于 `<stdio.h>` 中。 |

##### 行为等价于
```c
clearerr(stream);              // 清除标志
fseek(stream, 0, SEEK_SET);  // 重置到文件开头
```

##### 使用示例
```c
FILE *fp = fopen("data.txt", "r");
// 读取一部分数据后...
rewind(fp);   // 回到文件开头，同时清除 feof/ferror 标志
// 可以重新从开头读取
```

#### 1. `mkdir` —— 创建目录

##### 函数原型
```c
#include <sys/stat.h>
#include <sys/types.h>

int mkdir(const char *pathname, mode_t mode);
```

##### 功能说明
创建一个名为 `pathname` 的新目录。新目录的权限由 `mode` 参数指定，并受进程的 `umask` 影响。

##### 返回值
- **成功**：返回 `0`。
- **失败**：返回 `-1`，并设置 `errno`（如 `EEXIST` 表示文件已存在，`EACCES` 表示权限不足等）。

##### 所需头文件

| 头文件                   | 必要性       | 说明                                                         |
| ------------------------ | ------------ | ------------------------------------------------------------ |
| `#include <sys/stat.h>`  | **必须**     | 提供 `mkdir` 函数声明，以及 `S_IRUSR`、`S_IWUSR`、`S_IXUSR` 等文件权限宏定义。POSIX 标准规定文件状态相关函数的声明位于此头文件中。 |
| `#include <sys/types.h>` | **强烈建议** | 提供 `mode_t` 类型定义。虽然 `<sys/stat.h>` 在多数系统中已间接包含，但显式引入可提升代码可移植性。 |

##### 参数详解
| 参数       | 说明                                                      |
| ---------- | --------------------------------------------------------- |
| `pathname` | 要创建的目录路径（绝对路径或相对路径）                    |
| `mode`     | 目录权限（与 `open` 的 `mode` 参数相同），受 `umask` 影响 |

##### 使用示例
```c
#include <sys/stat.h>
#include <sys/types.h>
#include <stdio.h>

int main() {
    // 创建目录，权限为 rwxr-x--x
    int ret = mkdir("test_dir", 
                    S_IRUSR | S_IWUSR | S_IXUSR |  // 所有者: 读+写+执行
                    S_IRGRP | S_IXGRP |            // 所属组: 读+执行
                    S_IXOTH);                      // 其他: 执行
    printf("mkdir: %d\n", ret);
    return 0;
}
```

##### 注意事项
- `mkdir` **只能创建目录**，不能创建普通文件。
- 创建目录时，**父目录必须存在**，否则返回 `-1`（`ENOENT`）。
- 权限 `mode` 会被进程的 `umask` 过滤，最终权限为 `mode & ~umask`。

#### 2. `rmdir` —— 删除空目录

##### 函数原型
```c
#include <unistd.h>

int rmdir(const char *pathname);
```

##### 功能说明
删除一个**空目录**。目录必须为空（除了 `.` 和 `..` 之外没有其他目录项），否则删除失败。

##### 返回值
- **成功**：返回 `0`。
- **失败**：返回 `-1`，并设置 `errno`（如 `ENOTEMPTY` 表示目录非空，`ENOENT` 表示目录不存在）。

##### 所需头文件

| 头文件                | 必要性   | 说明                                                    |
| --------------------- | -------- | ------------------------------------------------------- |
| `#include <unistd.h>` | **必须** | POSIX 标准规定 `rmdir` 函数的声明位于 `<unistd.h>` 中。 |

##### 参数详解
| 参数       | 说明               |
| ---------- | ------------------ |
| `pathname` | 要删除的空目录路径 |

##### 使用示例
```c
#include <unistd.h>
#include <stdio.h>

int main() {
    int ret = rmdir("test_dir");
    printf("rmdir: %d\n", ret);
    return 0;
}
```

##### 注意事项
- `rmdir` **只能删除空目录**。如果目录非空，需要先递归删除其中的所有文件和子目录。
- 若目录是符号链接，`rmdir` 会删除链接指向的目录（而非链接本身），且要求目标目录为空。

#### 3. `remove` —— 删除文件或空目录

##### 函数原型
```c
#include <stdio.h>

int remove(const char *pathname);
```

##### 功能说明
删除指定的文件或**空目录**。对于文件，效果等同于 `unlink()`函数；对于目录，效果等同于 `rmdir()`函数。整体行为类似 Shell 中的 `rm` 命令。

> ###### 什么是 `unlink`？
>
> `unlink` 是一个系统调用，它的核心作用是**从文件系统中移除一个目录项（文件名），并减少该文件的硬链接计数**。

##### 返回值
- **成功**：返回 `0`。
- **失败**：返回 `-1`，并设置 `errno`。

##### 所需头文件

| 头文件               | 必要性   | 说明                                                  |
| -------------------- | -------- | ----------------------------------------------------- |
| `#include <stdio.h>` | **必须** | C 标准库规定 `remove` 函数的声明位于 `<stdio.h>` 中。 |

##### 参数详解
| 参数       | 说明                   |
| ---------- | ---------------------- |
| `pathname` | 要删除的文件或目录路径 |

##### 使用示例
```c
#include <stdio.h>

int main() {
    // 删除文件
    printf("remove file: %d\n", remove("test.txt"));
    
    // 删除空目录
    printf("remove dir: %d\n", remove("test_dir"));
    
    return 0;
}
```

#### `unlink` 说明

##### `unlink` 的特殊行为（与直觉相反）

###### 1. 如果进程正在使用该文件，文件内容仍然可读

这是 `unlink` 最容易被忽视的特性：

```c
int fd = open("temp.log", O_RDWR);
unlink("temp.log");    // 文件名被删除，目录里看不到了
write(fd, "data", 4);  // ✅ 仍然可以读写！
lseek(fd, 0, SEEK_SET);
read(fd, buf, 4);      // ✅ 仍然可以读写！
close(fd);             // 此时文件才真正被删除
```

这种特性在创建**临时文件**时非常有用：文件打开后立即 `unlink`，进程退出时（`close` 或进程终止）文件会自动被清理，无需额外调用 `remove`。

###### 2. `remove` 对不同文件类型的处理

| 目标类型     | `remove` 的底层调用 | 行为                                       |
| ------------ | ------------------- | ------------------------------------------ |
| **普通文件** | `unlink(path)`      | 解除文件名到 inode 的硬链接                |
| **目录**     | `rmdir(path)`       | 要求目录为空，否则失败                     |
| **符号链接** | `unlink(path)`      | 删除链接文件本身，**不跟随**链接指向的目标 |

##### 注意事项
- `remove` 对于**普通文件**：直接删除文件（减少链接计数）。
- `remove` 对于**目录**：要求目录必须为空，否则失败。
- `remove` 对于**符号链接**：删除链接本身（而非链接指向的目标），与 `rmdir` 行为不同。
