### 一、对话框基本概念

#### 什么是对话框

对话框（Dialog）是一种特殊的窗口，用于在用户界面中向用户显示信息，或者在需要时获取用户的输入响应。之所以称为"对话框"，是因为它使计算机与用户之间构成了一种对话：

- 通知用户某些信息（如操作成功、错误提示）
- 请求用户输入数据（如填写表单、选择文件）
- 两者兼有（如设置窗口、确认操作）

#### 对话框的分类

在Qt中，对话框主要分为两种：

| 类型             | 说明                         | 特点                               |
| ---------------- | ---------------------------- | ---------------------------------- |
| **模态对话框**   | 打开后不能对其他窗口进行操作 | 使用 `exec()` 显示，阻塞程序执行   |
| **非模态对话框** | 打开后仍可对其他窗口进行操作 | 使用 `show()` 显示，不阻塞程序执行 |

---

### 二、标准对话框

#### 概念引入

标准对话框是Qt内置的一系列通用对话框，拿来即可使用，无需重复开发。就像手机买来就自带相机、短信等应用，微信拍照时直接调用系统相机即可。

#### Qt内置的标准对话框

| 类名           | 功能                                 |
| -------------- | ------------------------------------ |
| `QColorDialog` | 选择颜色                             |
| `QFileDialog`  | 选择文件或目录                       |
| `QFontDialog`  | 选择字体                             |
| `QInputDialog` | 允许用户输入一个值并返回             |
| `QMessageBox`  | 模态消息框，用于显示信息、询问问题等 |

> 这些对话框在所有程序中几乎相同，因此无需在每个程序中重复实现。

### 三、模态对话框

#### 执行方式

模态对话框使用 `exec()` 方法显示：

```cpp
QDialog dialog(this);
dialog.exec();  // 模态，阻塞程序执行
```

#### 原理说明

`exec()` 内部实际上是一个**死循环**（事件循环），它会一直等待用户操作，直到对话框被关闭才会退出循环。因此，`exec()` 后面的代码不会被执行，其他窗口也无法响应操作。

#### 特点

- 对话框打开后，**不能**对应用程序的其他窗口进行操作
- 尝试点击其他窗口时，对话框会闪烁并发出警告声音
- `exec()` 后面的代码会被阻塞，直到对话框关闭

#### 代码示例

```cpp
// 点击"新建"菜单，弹出模态对话框
connect(ui->actionNewFile, &QAction::triggered, this, [=]() {
    QDialog dialog(this);
    dialog.exec();  // 代码在此阻塞，其他窗口无法操作
    qDebug() << "对话框已关闭";  // 关闭后才执行
});
```

### 四、非模态对话框

#### 执行方式

非模态对话框使用 `show()` 方法显示：

```cpp
QDialog dialog(this);
dialog.show();  // 非模态，不阻塞程序执行
```

#### 特点

- 对话框打开后，**可以**继续操作应用程序的其他窗口
- `show()` 立即返回，不阻塞后续代码执行

#### ⚠️ 常见问题：对话框一闪而过

如果直接在栈上创建对话框对象，由于 `show()` 不阻塞，函数结束后对象会被销毁，导致对话框一闪而过：

```cpp
// ❌ 错误写法：对话框会一闪而过
connect(ui->actionNewFile, &QAction::triggered, this, [=]() {
    QDialog dialog(this);  // 栈上创建
    dialog.show();         // 非阻塞，立即返回
    qDebug() << "打开对话框";
    // 函数结束，dialog 被销毁，对话框消失
});
```

#### ✅ 解决方案：使用 new 在堆上创建

```cpp
// 使用 new 在堆上创建
QDialog* dialog = new QDialog(this);
dialog->show();
```

#### ⚠️ 潜在问题：内存泄漏

使用 `new` 虽然解决了对话框消失的问题，但产生了新的隐患：

- 每次点击都会 `new` 一个新的对话框对象
- 关闭对话框时，对象**并不会自动销毁**（只有父窗口关闭时才统一释放）
- 如果频繁打开关闭对话框，会造成**内存泄漏**

#### ✅ 最终解决方案：设置关闭时自动销毁

```cpp
QDialog* dialog = new QDialog(this);
dialog->setAttribute(Qt::WA_DeleteOnClose);  // 关闭时自动删除对象
dialog->show();
```

`Qt::WA_DeleteOnClose` 属性的作用：当部件关闭时，自动 `delete` 该对象，释放内存。

### 五、完整代码示例

```cpp
MainWindow::MainWindow(QWidget *parent) :
    QMainWindow(parent),
    ui(new Ui::MainWindow)
{
    ui->setupUi(this);

    // 连接"新建"菜单的触发信号
    connect(ui->actionNewFile, &QAction::triggered, this, [=]() {
        // ====== 模态对话框 ======
        // QDialog dialog(this);
        // dialog.exec();  // 阻塞，其他窗口不可操作
        // qDebug() << "模态对话框已关闭";

        // ====== 非模态对话框（推荐写法） ======
        QDialog* dialog = new QDialog(this);
        dialog->resize(200, 100);
        dialog->show();  // 非阻塞，其他窗口可操作
        dialog->setAttribute(Qt::WA_DeleteOnClose);  // 关闭时自动释放

        qDebug() << "打开非模态对话框";
    });
}
```

### 六、总结对比

| 对比项           | 模态对话框                   | 非模态对话框             |
| ---------------- | ---------------------------- | ------------------------ |
| 显示方法         | `exec()`                     | `show()`                 |
| 是否阻塞         | 阻塞，后面的代码不执行       | 不阻塞，立即返回         |
| 能否操作其他窗口 | ❌ 不能                       | ✅ 可以                   |
| 对象生命周期     | 栈上即可，exec阻塞直至关闭   | 需堆上创建，注意内存管理 |
| 适用场景         | 必须用户确认后才能继续的操作 | 辅助面板、查找替换等     |

**非模态对话框的使用要点**：
1. 使用 `new` 在堆上创建对象
2. 设置 `Qt::WA_DeleteOnClose` 属性防止内存泄漏
3. 可以同时打开多个非模态对话框
