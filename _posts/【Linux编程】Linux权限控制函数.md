# Linux 文件权限基础笔记

---

## 一、什么是权限

在 Linux 系统中，**权限**指的是用户对文件或目录的**控制权**，即是否能够**读取、写入或执行**某个文件。

由于 Linux 遵循 **“一切皆文件”** 的设计思想，因此不仅普通文件有权限，**内存**、**进程**等系统资源也以文件的形式存在，并受到权限体系的管控。

---

## 二、查看权限：`ls -l`

使用 `ls -l` 命令可以查看当前目录下各文件的详细权限信息。

示例输出：

```bash
root@aliyun:~# ls -l
total 16
drwxr-xr-x 2 root root 4096 Aug  8 21:50 code
drwxr-xr-x 3 root root 4096 Aug  9 18:20 projects
-rwxr-xr-x 1 root root 16528 Aug  8 21:50 test
drwxr-xr-x 2 root root 4096 Aug  8 21:27 workspace
lrwxrwxrwx 1 root root 0     Aug  8 21:24 root -> /
```

---

## 三、输出字段详解

每一行由以下字段组成（从左到右）：

| 字段位置    | 含义              |
| ----------- | ----------------- |
| **第 1 列** | 文件类型 + 权限位 |
| **第 2 列** | 硬链接数          |
| **第 3 列** | 文件所有者        |
| **第 4 列** | 文件所属组        |
| **第 5 列** | 文件大小（字节）  |
| **第 6 列** | 文件最后修改时间  |
| **第 7 列** | 文件名            |

---

## 四、第 1 列详解：文件类型 + 权限

### 1. 第一个字符 —— 文件类型

| 字符 | 含义               |
| ---- | ------------------ |
| `-`  | 普通文件           |
| `d`  | 目录               |
| `l`  | 符号链接（软链接） |
| `b`  | 块设备文件         |
| `c`  | 字符设备文件       |
| `s`  | 套接字文件         |
| `p`  | 管道文件           |

> 日常最常见的是 `-`（文件）、`d`（目录）和 `l`（链接）。

---

### 2. 后续九个字符 —— 权限位

权限位分为三组，每组三个字符：

| 组序                     | 对应对象                         |
| ------------------------ | -------------------------------- |
| **第 1 组**（字符 2~4）  | 文件所有者的权限                 |
| **第 2 组**（字符 5~7）  | 文件所有者所在组中其他用户的权限 |
| **第 3 组**（字符 8~10） | 其他组用户的权限                 |

每组中的三个字符含义：

| 字符 | 含义              |
| ---- | ----------------- |
| `r`  | 可读（read）      |
| `w`  | 可写（write）     |
| `x`  | 可执行（execute） |
| `-`  | 无对应权限        |

---

## 五、示例解析

以其中一行为例：

```bash
-rwxr-xr-x 1 root root 16528 Aug 8 21:50 test
```

| 部分          | 解析                               |
| ------------- | ---------------------------------- |
| `-`           | 这是一个普通文件                   |
| `rwx`         | 所有者（root）有读、写、执行权限   |
| `r-x`         | 所属组用户有读、执行权限，无写权限 |
| `r-x`         | 其他用户有读、执行权限，无写权限   |
| `1`           | 硬链接数为 1                       |
| `root`        | 文件所有者为 root                  |
| `root`        | 文件所属组为 root                  |
| `16528`       | 文件大小为 16528 字节              |
| `Aug 8 21:50` | 最后修改时间                       |
| `test`        | 文件名                             |

---

再如目录：

```bash
drwxr-xr-x 2 root root 4096 Aug 8 21:50 code
```

| 部分  | 解析                             |
| ----- | -------------------------------- |
| `d`   | 这是一个目录                     |
| `rwx` | 所有者可读、可写、可进入（执行） |
| `r-x` | 所属组可读、可进入，不可写       |
| `r-x` | 其他用户可读、可进入，不可写     |

---

链接文件示例：

```bash
lrwxrwxrwx 1 root root 0 Aug 8 21:24 root -> /
```

| 部分        | 解析                                                         |
| ----------- | ------------------------------------------------------------ |
| `l`         | 这是一个符号链接                                             |
| `rwxrwxrwx` | 所有用户都有读写执行权限（链接文件本身权限通常为全开，实际权限取决于目标文件） |
| `root -> /` | 链接名为 `root`，指向目标 `/`                                |

---

## 六、核心要点总结

- 权限控制对象：**读（r）、写（w）、执行（x）**
- 权限作用主体：**所有者（User）、所属组（Group）、其他用户（Others）**
- 查看命令：`ls -l`
- 文件类型判断：看第一个字符（`-` 文件、`d` 目录、`l` 链接）
- 权限判断：看后九位，三位一组

# Linux 进程用户身份：真实用户与有效用户

---

## 一、核心概念

在 Linux 进程管理中，每个进程都关联着两个重要的用户 ID：

| 概念            | 英文                  | 含义                                               | 特点                                   |
| --------------- | --------------------- | -------------------------------------------------- | -------------------------------------- |
| **真实用户 ID** | Real UID（RUID）      | **“你是谁”** —— 启动进程的用户的身份               | 静态不变，主要用于“记账”和标识进程归属 |
| **有效用户 ID** | Effective UID（EUID） | **“你以谁的权限在干活”** —— 进程实际使用的权限身份 | 动态可变，决定进程能访问哪些资源       |

---

## 二、两者的区别与关系

| 对比维度 | 真实用户（RUID）        | 有效用户（EUID）                           |
| -------- | ----------------------- | ------------------------------------------ |
| 本质     | 进程发起者的身份标识    | 进程当前的权限身份                         |
| 是否可变 | ❌ 一般不变              | ✅ 可根据进程运行状态动态切换               |
| 作用     | 标识进程归属、审计/记账 | 内核进行权限检查（如访问文件）时的判断依据 |
| 获取函数 | `getuid()`              | `geteuid()`                                |

---

## 三、典型场景示例

### 场景：普通用户使用 `sudo` 提权

1. 用户以普通身份登录系统 → **真实用户 = 普通用户**
2. 执行 `sudo` 命令 → 有效用户临时提升为 `root`
3. 此时：
   - **真实用户**仍然是普通用户（不变）
   - **有效用户**变为 `root`（拥有最高权限）

> ✅ 真实用户是“身份”，有效用户是“权限状态”。身份不变，但权限可以临时提升或降低。

---

## 四、相关系统调用

| 函数        | 返回值              | 说明                           |
| ----------- | ------------------- | ------------------------------ |
| `getuid()`  | 真实用户 ID（RUID） | 获取启动进程的用户身份         |
| `geteuid()` | 有效用户 ID（EUID） | 获取当前进程实际使用的权限身份 |

> 内核在进行权限检查时，使用的是 **有效用户 ID（EUID）**，而非真实用户 ID。

---

## 五、用户 ID 数值范围与含义

| 数值范围     | 含义                                                         |
| ------------ | ------------------------------------------------------------ |
| **0**        | **超级用户（root）**，拥有系统最高权限                       |
| 1 ~ 999      | 不存在这些值                                                 |
| 1000 ~ 9999  | 系统保留 ID，通常用于系统账户、后台服务、守护进程等（如 `systemd`、`tty` 等） |
| 10000 及以上 | 其他普通用户（部分发行版从 1000 起即为普通用户，具体取决于配置） |

> 📌 不同 Linux 发行版的具体数值范围可能略有差异，但 **0 为 root** 是统一标准。

---

## 六、核心要点总结

1. **真实用户（RUID）**：标识“谁启动了进程”，一般不改变。
2. **有效用户（EUID）**：决定“进程当前拥有什么权限”，可动态切换。
3. 权限检查时，内核看的是 **有效用户 ID**，而不是真实用户 ID。
4. `sudo` 提权的本质：**真实用户不变，有效用户临时变为 root**。
5. `getuid()` 和 `geteuid()` 分别用于获取这两种 ID。

# Linux 文件权限与 `chmod` 完全笔记

---

## 一、基础权限回顾

Linux 文件权限分为三组，每组三个权限位：

| 权限 | 含义 | 数值 |
| ---- | ---- | ---- |
| `r`  | 读   | 4    |
| `w`  | 写   | 2    |
| `x`  | 执行 | 1    |
| `-`  | 无   | 0    |

权限组合为三组：

- **所有者（User）**
- **所属组（Group）**
- **其他用户（Others）**

---

## 二、特殊权限位（SUID / SGID / Sticky Bit）

除了基础的 `rwx`，还有三个特殊权限位，会顶替原本 `x` 的位置显示。

| 特殊权限       | 字符表现  | 作用对象    | 含义                                                         |
| -------------- | --------- | ----------- | ------------------------------------------------------------ |
| **SUID**       | `s` / `S` | 可执行文件  | 执行时，进程以**文件所有者**身份运行，有效用户变为文件所有者 |
| **SGID**       | `s` / `S` | 文件 / 目录 | • 文件：执行时以**文件所属组**身份运行 <br> • 目录：新建文件/目录继承父目录的组 |
| **Sticky Bit** | `t` / `T` | 目录        | 只有**文件所有者、目录所有者或 root** 才能删除/重命名文件    |

📍 位置对应关系：

- **SUID** → 顶替第一组（所有者）的 `x`
- **SGID** → 顶替第二组（所属组）的 `x`
- **Sticky Bit** → 顶替第三组（其他用户）的 `x`

---

### `s` / `S` 与 `t` / `T` 的区别

| 显示        | 含义                                     | 说明                           |
| ----------- | ---------------------------------------- | ------------------------------ |
| `s`（小写） | SUID/SGID **生效** + 执行权限存在        | 原本就有 `x`，特殊位生效       |
| `t`（小写） | Sticky Bit **生效** + 执行权限存在       | 原本有 `x`，粘滞位生效         |
| `S`（大写） | SUID/SGID **设置但无效** + 执行权限缺失  | 原本无 `x`，特殊位无法正常工作 |
| `T`（大写） | Sticky Bit **设置但无效** + 执行权限缺失 | 原本无 `x`，粘滞位实际无效     |

⭐ 核心理解：

- **`s` 涉及提权 / 降权**（有效用户/组变更）
- **`t` 涉及删除权限控制**

---

## 三、特殊权限实际示例

### 1. SUID 示例

```bash
-rwsr-xr-x 1 root root 12345 /usr/bin/passwd
```

- `s` 出现在所有者位（`rws`）
- 任何用户执行 `passwd` 时，以 **root** 身份运行
- 小写 `s` 表示原本有 `x` 权限

---

### 2. SGID 示例（目录）

```bash
drwxrwsr-x 2 root staff 4096 /shared
```

- `s` 出现在组权限位（`rws`）
- 在该目录下新建文件，所属组自动继承为 `staff`
- 小写 `s` 表示目录本身有 `x` 权限

---

### 3. Sticky Bit 示例

```bash
drwxrwxrwt 20 root root 4096 /tmp
```

- 末尾的 `t` 表示粘滞位
- `/tmp` 目录任何人可读写，但只能删除自己的文件
- 小写 `t` 表示目录有 `x` 权限

---

## 四、`chmod` 命令详解

### 全称
**Change Mode** —— 修改文件或目录的访问权限

---

### 使用方式

#### 1. 符号方式（字母）

```bash
chmod u+x file    # 所有者增加执行权限
chmod g-w file    # 删除组的写权限
chmod o=r file    # 设置其他人的权限为只读
chmod a+x file    # 所有用户增加执行权限
```

#### 2. 数字方式（八进制）⭐ 重点

```bash
chmod 755 file
chmod 644 file
chmod 777 file
```

---

## 五、数字权限的计算方法

### 单个权限数值

| 权限 | 数值 |
| ---- | ---- |
| `r`  | 4    |
| `w`  | 2    |
| `x`  | 1    |
| `-`  | 0    |

### 权限组合计算

| 权限  | 计算  | 结果 |
| ----- | ----- | ---- |
| `rwx` | 4+2+1 | 7    |
| `rw-` | 4+2+0 | 6    |
| `r-x` | 4+0+1 | 5    |
| `r--` | 4+0+0 | 4    |
| `-wx` | 0+2+1 | 3    |
| `-w-` | 0+2+0 | 2    |
| `--x` | 0+0+1 | 1    |
| `---` | 0+0+0 | 0    |

---

## 六、三位数字权限结构

`chmod` 的三位数字分别代表：

| 位置  | 代表对象             | 说明             |
| ----- | -------------------- | ---------------- |
| 第1位 | **所有者（User）**   | 文件所有者的权限 |
| 第2位 | **所属组（Group）**  | 文件所属组的权限 |
| 第3位 | **其他人（Others）** | 其他用户的权限   |

格式：`chmod [所有者][组][其他人] 文件名`

---

### 示例推导

#### `chmod 755 file`

| 对象   | 数字 | 二进制 | 权限  |
| ------ | ---- | ------ | ----- |
| 所有者 | 7    | 111    | `rwx` |
| 组     | 5    | 101    | `r-x` |
| 其他人 | 5    | 101    | `r-x` |

结果：`-rwxr-xr-x`

---

#### `chmod 644 file`

| 对象   | 数字 | 二进制 | 权限  |
| ------ | ---- | ------ | ----- |
| 所有者 | 6    | 110    | `rw-` |
| 组     | 4    | 100    | `r--` |
| 其他人 | 4    | 100    | `r--` |

结果：`-rw-r--r--`

---

#### `chmod 777 file`（⚠️ 最大权限，慎用）

| 对象   | 数字 | 权限  |
| ------ | ---- | ----- |
| 所有者 | 7    | `rwx` |
| 组     | 7    | `rwx` |
| 其他人 | 7    | `rwx` |

结果：`-rwxrwxrwx`

---

## 七、四位数字（含特殊权限）

格式：`chmod [特殊权限][所有者][组][其他人] 文件名`

| 特殊权限位数值 | 含义       |
| -------------- | ---------- |
| 4              | SUID       |
| 2              | SGID       |
| 1              | Sticky Bit |

示例：

```bash
chmod 4755 file   # SUID + rwxr-xr-x
chmod 1777 dir    # Sticky Bit + rwxrwxrwx（如 /tmp）
```

---

## 八、常用权限速查表

| 数字    | 权限        | 常用场景                   |
| ------- | ----------- | -------------------------- |
| **755** | `rwxr-xr-x` | 可执行文件（脚本/程序）    |
| **644** | `rw-r--r--` | 普通文件（配置/文档）      |
| **600** | `rw-------` | 私密文件（如密钥）         |
| **700** | `rwx------` | 仅所有者可操作             |
| **777** | `rwxrwxrwx` | 完全开放（⚠️ 危险）         |
| **755** | `rwxr-xr-x` | 目录（需执行权限才能进入） |

---

## 九、实战验证

```bash
# 查看当前权限
ls -l test

# 修改为 755
chmod 755 test
ls -l test
# 输出：-rwxr-xr-x 1 root root 16528 Aug 8 21:50 test

# 修改为 644
chmod 644 test
ls -l test
# 输出：-rw-r--r-- 1 root root 16528 Aug 8 21:50 test
```

## 十、补充：提权相关（SUID 与 `setuid(0)`）

在进程中执行 `setuid(0)` 实现提权，需满足以下条件之一：

- **真实用户为 root** → 直接以 root 用户执行文件即可
- **有效用户为 root** → 通过以下两步实现：
  1. `chown root.root ./file`   # 将文件所有者改为 root
  2. `chmod 6755 ./file`        # 设置 SUID + SGID（使有效用户变为 root）

> 此时进程运行时，**有效用户**变为 root，而**真实用户**保持不变。
