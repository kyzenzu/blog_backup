### 获取进程信息函数详解

---

#### 1. `getpid` —— 获取进程ID

##### 函数原型
```c
#include <unistd.h>
#include <sys/types.h>

pid_t getpid(void);
```

##### 功能说明
返回当前进程的**唯一标识符**（进程ID）。

##### 返回值
当前进程的 PID（进程ID），类型为 `pid_t`。该函数**总是成功**，不会返回错误。

##### 所需头文件

| 头文件                   | 必要性       | 说明                                                         |
| ------------------------ | ------------ | ------------------------------------------------------------ |
| `#include <unistd.h>`    | **必须**     | POSIX 标准规定 `getpid`、`getppid`、`getpgrp`、`getpgid` 等进程信息相关函数的声明位于 `<unistd.h>` 中。 |
| `#include <sys/types.h>` | **强烈建议** | 提供 `pid_t` 类型定义。虽然 `<unistd.h>` 在多数系统中已间接包含，但显式引入可提升代码可移植性，符合 POSIX 规范。 |

##### 特点
- PID 在系统运行期间唯一，且不会复用（除非 PID 值达到最大值后回绕）。
- 该函数是系统调用，但开销极小。

##### 常见用途
- 生成临时文件名（如 `/tmp/myapp_%d`）
- 写日志区分不同进程实例
- 作为其他系统调用（如 `kill`、`setpgid`）的参数

---

#### 2. `getppid` —— 获取父进程ID

##### 函数原型
```c
#include <unistd.h>
#include <sys/types.h>

pid_t getppid(void);
```

##### 功能说明
返回当前进程的**父进程**PID。

##### 返回值
父进程的 PID，类型为 `pid_t`。该函数**总是成功**，不会返回错误。

##### 所需头文件

| 头文件                   | 必要性       | 说明                                                      |
| ------------------------ | ------------ | --------------------------------------------------------- |
| `#include <unistd.h>`    | **必须**     | POSIX 标准规定 `getppid` 的函数声明位于 `<unistd.h>` 中。 |
| `#include <sys/types.h>` | **强烈建议** | 提供 `pid_t` 类型定义。                                   |

##### 特殊场景
如果父进程在子进程之前退出，子进程会被 **init（PID=1）** 或 **systemd** 收养，此时 `getppid()` 返回 `1`。

##### 常见用途
守护进程（Daemon）常通过检查 `getppid() == 1` 来判断自己是否已被 init 收养。

---

#### 3. `getpgrp` —— 获取当前进程组ID

##### 函数原型
```c
#include <unistd.h>
#include <sys/types.h>

pid_t getpgrp(void);
```

##### 功能说明
返回当前进程所属的**进程组**的 PGID（进程组ID）。

##### 返回值
当前进程的进程组 ID（PGID），类型为 `pid_t`。该函数**总是成功**，不会返回错误。

##### 所需头文件

| 头文件                   | 必要性       | 说明                                                      |
| ------------------------ | ------------ | --------------------------------------------------------- |
| `#include <unistd.h>`    | **必须**     | POSIX 标准规定 `getpgrp` 的函数声明位于 `<unistd.h>` 中。 |
| `#include <sys/types.h>` | **强烈建议** | 提供 `pid_t` 类型定义。                                   |

##### 本质
在大多数实现中，`getpgrp(void)` 等价于 `getpgid(0)`。

##### 注意
进程组的 PGID 通常等于该组**首进程**（组长）的 PID。

##### 常见用途
用于作业控制（Shell 中的前台/后台任务）。当在终端按 `Ctrl+C` 时，信号会发送给整个进程组，而不只是单个进程。

---

#### 4. `getpgid` —— 获取指定进程的进程组ID

##### 函数原型
```c
#include <unistd.h>
#include <sys/types.h>

pid_t getpgid(pid_t pid);
```

##### 功能说明
查询**任意进程**的进程组 ID。这是 `getpgrp` 的通用版本。

##### 返回值
- **成功**：返回目标进程的 PGID。
- **失败**：返回 `-1`，并设置 `errno`（通常是因为权限不足或 PID 不存在）。

##### 所需头文件

| 头文件                   | 必要性       | 说明                                                      |
| ------------------------ | ------------ | --------------------------------------------------------- |
| `#include <unistd.h>`    | **必须**     | POSIX 标准规定 `getpgid` 的函数声明位于 `<unistd.h>` 中。 |
| `#include <sys/types.h>` | **强烈建议** | 提供 `pid_t` 类型定义。                                   |

##### 参数详解
| 参数  | 说明                                                         |
| ----- | ------------------------------------------------------------ |
| `pid` | 目标进程 PID。传入 `0` 表示查询当前进程的进程组 ID（等同于 `getpgrp()`）。 |

##### 注意
查询其他进程时，目标进程与调用进程需属于**同一会话（Session）**，否则可能无权限。

##### 常见用途
- 获取任意进程的进程组信息
- 配合 `setpgid` 进行进程组管理

---

#### 5. `getpriority` —— 获取进程调度优先级

##### 函数原型
```c
#include <sys/time.h>
#include <sys/resource.h>

int getpriority(int which, int who);
```

##### 功能说明
获取进程、进程组或用户的调度优先级（Nice 值）。该函数不仅针对单个进程，还可以作用于**进程组**或**用户**。

##### 返回值
- **成功**：返回 Nice 值（范围 -20 到 19）。
- **失败**：返回 `-1`，并设置 `errno`。

##### 所需头文件

| 头文件                      | 必要性   | 说明                                                         |
| --------------------------- | -------- | ------------------------------------------------------------ |
| `#include <sys/time.h>`     | **必须** | 提供系统时间相关类型定义（`struct timeval` 等）。            |
| `#include <sys/resource.h>` | **必须** | 提供 `getpriority`、`setpriority` 的函数声明，以及 `PRIO_PROCESS`、`PRIO_PGRP`、`PRIO_USER` 等宏定义。POSIX 标准规定资源操作相关函数的声明位于此头文件中。 |

##### 参数详解
| 参数    | 说明                                                         |
| ------- | ------------------------------------------------------------ |
| `which` | 作用范围：`PRIO_PROCESS`（进程）、`PRIO_PGRP`（进程组）、`PRIO_USER`（用户）。 |
| `who`   | 根据 `which` 传入对应的 ID（PID / PGID / UID）。传入 `0` 代表调用者自身（当前进程 / 当前进程组 / 当前用户）。 |

##### ⚠️ 返回值陷阱（极易踩坑）

Linux 内核实际维护的优先级范围是 **0（最高）** 到 **139（最低）**（包含实时优先级），但 `getpriority` 返回的是 **Nice 值**，范围是 **-20（最高）** 到 **19（最低）**。

**关键陷阱**：函数成功时返回 Nice 值；**失败时返回 -1**。但由于 Nice 值本身可以是 `-1`，所以**不能**单纯用 `if (ret == -1)` 判断错误，必须结合 `errno` 变量：

```c
errno = 0;  // 重要：先清空 errno
int nice = getpriority(PRIO_PROCESS, 0);
if (nice == -1 && errno != 0) {
    perror("getpriority failed");  // 真出错
} else {
    printf("Current nice: %d\n", nice);  // 正常拿到了 -1 的优先级
}
```

##### 常见用途
- 检查当前进程的 Nice 值
- 在调整优先级前查询当前值

---

#### 快速参考

| 函数          | 头文件             | 核心用途            | 是否可能失败               |
| ------------- | ------------------ | ------------------- | -------------------------- |
| `getpid`      | `<unistd.h>`       | 获取当前进程 PID    | ❌ 总是成功                 |
| `getppid`     | `<unistd.h>`       | 获取父进程 PID      | ❌ 总是成功                 |
| `getpgrp`     | `<unistd.h>`       | 获取当前进程组 PGID | ❌ 总是成功                 |
| `getpgid`     | `<unistd.h>`       | 获取指定进程 PGID   | ✅ 可能失败                 |
| `getpriority` | `<sys/resource.h>` | 获取 Nice 值        | ✅ 可能失败（需检查 errno） |

### 设置进程信息函数详解

---

#### 1. `setpgid` —— 设置进程组ID

##### 函数原型
```c
#include <unistd.h>

int setpgid(pid_t pid, pid_t pgid);
```

##### 功能说明
设置指定进程的进程组ID（PGID），可以将进程加入已有进程组，或创建新的进程组。

##### 返回值
- **成功**：返回 `0`。
- **失败**：返回 `-1`，并设置 `errno`。

##### 所需头文件

| 头文件                | 必要性   | 说明                                                         |
| --------------------- | -------- | ------------------------------------------------------------ |
| `#include <unistd.h>` | **必须** | POSIX 标准规定 `setpgid`、`getpgid`、`setpgrp` 等进程组相关函数的声明位于 `<unistd.h>` 中。 |

##### 参数详解
| 参数   | 说明                                                         |
| ------ | ------------------------------------------------------------ |
| `pid`  | 要修改的目标进程 ID。传入 `0` 表示修改**当前进程**。         |
| `pgid` | 目标进程组 ID。传入 `0` 表示将 `pid` 指定的进程**提升为组长**（创建新进程组，新 PGID 等于该进程的 PID）。 |

##### 限制与规则（极易出错）
1. **权限**：调用者的有效用户 ID（EUID）必须等于目标进程的真实用户 ID（RUID）或保存用户 ID（SUID），否则报错 `EPERM`。
2. **组长不能变**：若 `pid` 指定的进程已经是进程组组长（PID == PGID），操作失败（`EACCES`）。
3. **只能移动自己或子进程**：`pid` 必须等于调用者自身（`0`），或是调用者的**直接子进程**（且该子进程尚未执行 `exec` 族函数）。不能随意移动系统中任意进程。
4. **同会话限制**：`pid` 和 `pgid` 指定的进程必须在**同一个会话（Session）** 内。

##### 典型用途
Shell 在启动管道命令（如 `cmd1 | cmd2`）时，调用 `setpgid` 将所有命令放入同一个进程组，以实现作业控制。

---

#### 2. `setpgrp` —— 设置当前进程组ID（简化版）

##### 函数原型
```c
#include <unistd.h>

int setpgrp(void);
```

##### 功能说明
将**当前进程**设置为它所在进程组的**组长**，即创建一个新的进程组，新 PGID 等于当前进程的 PID。

##### 返回值
- **成功**：返回 `0`。
- **失败**：返回 `-1`，并设置 `errno`。

##### 所需头文件

| 头文件                | 必要性   | 说明                                                      |
| --------------------- | -------- | --------------------------------------------------------- |
| `#include <unistd.h>` | **必须** | POSIX 标准规定 `setpgrp` 的函数声明位于 `<unistd.h>` 中。 |

##### 本质
在大多数 Linux 实现中，`setpgrp(void)` 等价于 `setpgid(0, 0)`。

##### 注意事项
- 该函数在 POSIX 标准中有些“历史遗留”差异（不同 Unix 版本行为略有不同）。
- **推荐**：在 Linux 下使用更明确的 `setpgid(0, 0)` 以获得更好的可移植性。

##### 典型场景
常用于守护进程启动时的第一步，让进程脱离原终端控制，成为一个新的进程组领袖。

---

#### 3. `setpriority` —— 设置调度优先级

##### 函数原型
```c
#include <sys/time.h>
#include <sys/resource.h>

int setpriority(int which, int who, int prio);
```

##### 功能说明
设置进程、进程组或用户的调度优先级（Nice 值），用于调整系统资源的调度“友好度”。

##### 返回值
- **成功**：返回 `0`。
- **失败**：返回 `-1`，并设置 `errno`。

##### 所需头文件

| 头文件                      | 必要性   | 说明                                                         |
| --------------------------- | -------- | ------------------------------------------------------------ |
| `#include <sys/time.h>`     | **必须** | 提供系统时间相关类型定义（`struct timeval` 等）。            |
| `#include <sys/resource.h>` | **必须** | 提供 `setpriority`、`getpriority` 的函数声明，以及 `PRIO_PROCESS`、`PRIO_PGRP`、`PRIO_USER` 等宏定义。POSIX 标准规定资源操作相关函数的声明位于此头文件中。 |

##### 参数详解
| 参数    | 说明                                                         |
| ------- | ------------------------------------------------------------ |
| `which` | 作用范围：`PRIO_PROCESS`（进程）、`PRIO_PGRP`（进程组）、`PRIO_USER`（用户）。 |
| `who`   | 根据 `which` 传入对应的 ID（PID / PGID / UID）。传入 `0` 代表调用者自身。 |
| `prio`  | 要设置的 **Nice 值**，范围 **-20（最高优先级）** 到 **19（最低优先级）**。 |

##### 权限规则（非常重要）

| 操作                                         | 权限要求                                                     |
| -------------------------------------------- | ------------------------------------------------------------ |
| **降低优先级**（Nice 值调大，降低 CPU 占用） | 任何用户均可操作（如从 0 调到 10）                           |
| **提升优先级**（Nice 值调小，增加 CPU 占用） | **仅 root 用户**可将 Nice 值设为负数；普通用户只能设为 `0` 或正数，否则返回 `-1`，`errno` 为 `EPERM` |

##### 可移植性建议
虽然标准范围是 -20 ~ 19，但建议使用系统定义的宏 `PRIO_MIN` 和 `PRIO_MAX`，以增强代码可移植性。

#### 4. `nice` —— 改变当前进程优先级（简易版）

##### 函数原型
```c
#include <unistd.h>

int nice(int inc);
```

##### 功能说明
调整**当前进程**的 Nice 值。这是 `setpriority` 的一个更简单的封装，专门用于当前进程。

##### 返回值
- **成功**：返回**新的 Nice 值**。
- **失败**：返回 `-1`，并设置 `errno`。

##### 所需头文件

| 头文件                | 必要性   | 说明                                                   |
| --------------------- | -------- | ------------------------------------------------------ |
| `#include <unistd.h>` | **必须** | POSIX 标准规定 `nice` 函数的声明位于 `<unistd.h>` 中。 |

##### 参数详解
| 参数  | 说明                                                         |
| ----- | ------------------------------------------------------------ |
| `inc` | Nice 值的**增量**（变化量），而非绝对值。正值降低优先级，负值提高优先级（需要 root 权限）。 |

##### ⚠️ 返回值陷阱
`nice` 成功时也可能返回 `-1`（当新的 Nice 值恰好为 `-1` 时）。**必须结合 `errno` 判断错误**：

```c
errno = 0;
int new_nice = nice(10);
if (new_nice == -1 && errno != 0) {
    perror("nice failed");
} else {
    printf("New nice value: %d\n", new_nice);
}
```

##### 典型场景
- 后台批处理任务：`nice(19)` 将 CPU 优先级降至最低，避免干扰交互式应用。
- 编译大型程序：`nice -n 10 make` 降低其对系统的负载影响。

#### 5. 示例代码

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/time.h>
#include <sys/resource.h>

int main() {
    pid_t pid = getpid();

    printf("PID: %d\n", pid);
    printf("PGID: %d\n", getpgid(pid));
    printf("-------------------------------\n");

    printf("setpgid: %d\n", setpgid(pid, 1));
    printf("*PGID: %d\n", getpgid(pid));

    printf("setpgrp: %d\n", setpgrp());
    printf("*PGID: %d\n", getpgid(pid));
    printf("-------------------------------\n");

    printf("PRIORITY: %d\n", getpriority(PRIO_PROCESS, pid));
    printf("setpriority: %d\n", setpriority(PRIO_PGRP, pid, 5));
    printf("*PRIORITY: %d\n", getpriority(PRIO_PROCESS, pid));

    printf("nice: %d\n", nice(-2));
    printf("*PRIORITY: %d\n", getpriority(PRIO_PROCESS, pid));

    return 0;
}
```

先区分两个概念：**进程组（Process Group）**和 **会话（Session）**。

#### 进程组

进程组由多个进程组成，其中会有一个进程充当**组长进程**（Process Group Leader），组长的PID（进程ID）就是该进程组的PGID（进程组ID）。

当用户想完成一项工作时，可能需要用到多个进程协同进行，而进程组的作用就是为了能让用户**一次操作整个任务**。

例如，在Shell中输入：

```bash
grep "error" log.txt | wc -l
```

这里`grep`和`wc`是两个独立的进程，但它们被Shell放入了**同一个进程组**。当你按`Ctrl+C`时，内核发送`SIGINT`信号给这个**进程组**，两个进程同时被终止，而不是只终止其中一个。

**生命周期**：进程组的存在不依赖于组长是否存活。只要组内**还有至少一个进程**，该进程组就存在。即使组长退出了，组内其他进程依然属于该组（PGID不变）。

#### 会话

当进程组多了以后，就需要一个东西来管理这些进程组，这个东西就是会话。

换句话说，会话由多个进程组组成。每个会话会从进程中选择一个**首领进程**（Session Leader），而首领的PID就是会话的SID（会话ID）。

一般来说，启动一个 Shell进程（比如 `bash`）之后，就启动了一个会话，`bash` 进程作为这个会话的**首领进程**，这个会话的 SID 取自 `bash` 进程的 PID。同时，`bash` 进程独自成立一个进程组，并作为这个进程组的组长。

**生命周期**：会话的存活也独立于首领。但一旦会话首领退出，该会话中的所有进程组都会收到挂断信号（`SIGHUP`），默认行为是终止所有进程（这也是为什么关闭终端（SSH断开）时，里面的后台任务会消失的原因）。

**与终端的关系**：一个会话**最多**关联一个**控制终端**（Controlling Terminal，即物理终端、SSH伪终端等）。所有在该终端上启动的进程都属于这个会话。

使用终端启动一个 Shell进程（比如 `bash`），自然的启动了一个会话，在会话中还有几个概念：前台进程组和后台进程组。同一时刻**只有一个**进程组能拥有终端的控制权（即能读取键盘输入和向屏幕输出），这个组叫**前台进程组**。其他进程组叫**后台进程组**。

也就是说一个会话中，只有一个进程组能作为前台进程组获取终端的输入，剩下的进程组只能作为后台进程组并且只能向终端输出不能获取终端的输入。

假设你在SSH登录后，启动了 `bash` 进程，同时启动了一个会话。此时这个会话中只有一个 `bash` 进程独自成为一个进程组，此时的 `bash` 进程组作为会话的前台进程组获取终端的输入。然后启动了 `./start.sh &` 进程在后台运行，于是多了一个 `start.sh` 进程组作为会话的后台进程组；然后 `vim test.c`  启动了 `vim` 进程，此时 `bash`  进程组变为后台进程组，而 `vim` 进程组开始作为会话的前台进程组。

```text
【会话 Session】（SID = bash的PID）
│
├── 前台进程组（Foreground PG）  <--- 拥有终端控制权，能接收 Ctrl+C
│   └── vim 进程 (PID=1001, PGID=1001)  【组长】
│
├── 后台进程组1（Background PG） <--- 没有终端控制权，但可以输出
│   ├── start.sh 进程 (PID=1002, PGID=1002) 【组长】
│   └── sleep 子进程 (PID=1003, PGID=1002)  【同组】
│
└── 后台进程组2（Shell自己的组）
    └── bash 进程 (PID=999, PGID=999) 【会话首领 + 组长】
```

### 信号与终端的传导机制

- **Ctrl+C (SIGINT)** 和 **Ctrl+Z (SIGTSTP)**：**不是**发给某个进程，而是发给**前台进程组**（Foreground PG）。内核记录着当前终端的“前台组ID”，收到键盘中断时，内核向该组所有进程发送信号。
- **关闭终端（SIGHUP）**：终端关闭时，内核向**会话首领**（Shell）发送`SIGHUP`。Shell收到后，默认会向该会话内的**所有进程组**广播`SIGHUP`，导致所有进程退出。
	- **例外**：使用 `nohup` 命令启动的进程，会忽略`SIGHUP`；使用 `disown` 从Shell作业表中移除的进程，Shell不会再向它广播信号。

##### 实战代码理解：如何创建一个“守护进程”

看完这些概念，你就明白为什么标准的守护进程（如Nginx、MySQL后台进程）必须执行以下步骤了：

```c
pid_t pid = fork();
if (pid == 0) { // 子进程
    setsid();                    // 1. 创建新会话，成为首领（脱离原终端）
    setpgrp();                   // 2. 成为新进程组组长（可选，setsid已包含）
    // 此时，该进程已完全脱离原SSH会话的控制
    // 即使关闭终端，该进程也不会收到SIGHUP而被终止
    // ... 后续可继续 fork 并关闭标准输入输出 ...
}
```
