### `fcntl` 函数详解

#### 1. 函数原型
```c
int fcntl(int fd, int cmd, ... /* 可变参数 */ );
```

- **返回值**：成功取决于 `cmd`，失败返回 `-1` 并设置 `errno`。
- **可变参数**：第三个不定量参数根据 `cmd` 不同，可能是整数 `int`，也可能是结构体指针 `struct flock *`。

---

#### 2. 功能说明
`fcntl`（file control）是 Linux C 编程中一个**功能极其丰富**的系统调用，堪称文件操作的“瑞士军刀”。它能够对已打开的文件描述符执行多种控制操作，包括复制描述符、获取/设置文件状态标志、管理记录锁（文件锁）、设置异步 I/O 通知等。

---

#### 3. 返回值
- **成功**：返回值取决于具体的 `cmd` 命令（见下文各命令说明）。
- **失败**：返回 `-1`，并设置全局 `errno` 以指示具体错误。

---

#### 4. 所需头文件

| 头文件                | 必要性       | 说明                                                         |
| --------------------- | ------------ | ------------------------------------------------------------ |
| `#include <fcntl.h>`  | **必须**     | 提供 `fcntl` 函数声明，以及所有 `cmd` 常量（`F_DUPFD`、`F_GETFL`、`F_SETFL`、`F_GETLK`、`F_SETLK`、`F_SETLKW` 等）和 `struct flock` 结构体定义。此头文件是所有文件控制操作的核心接口所在地。 |
| `#include <unistd.h>` | **隐含必需** | 虽然 `fcntl` 的声明在 `<fcntl.h>` 中，但实际使用时通常配合 `open`、`close`、`read`、`write` 等文件操作函数，这些函数声明于 `<unistd.h>`。此外，`STDIN_FILENO`、`STDOUT_FILENO` 等标准描述符常量也定义于此。 |

---

#### 5. 主要功能分类（按 `cmd`）

| 功能分类                         | cmd 常量                           | 作用简述                                         |
| :------------------------------- | :--------------------------------- | :----------------------------------------------- |
| **复制描述符**                   | `F_DUPFD` / `F_DUPFD_CLOEXEC`      | 复制文件描述符，返回新 fd                        |
| **获取/设置 close-on-exec 标志** | `F_GETFD` / `F_SETFD`              | 读写 `FD_CLOEXEC` 标志，控制 exec 时是否自动关闭 |
| **获取/设置文件状态标志**        | `F_GETFL` / `F_SETFL`              | 读写 `O_NONBLOCK`、`O_APPEND` 等标志             |
| **管理记录锁**                   | `F_GETLK` / `F_SETLK` / `F_SETLKW` | **精细粒度的文件锁（重点）**                     |
| **管理信号/通知**                | `F_GETOWN` / `F_SETOWN`            | 设置异步 I/O 的属主进程                          |
| **管道容量**                     | `F_GETPIPE_SZ` / `F_SETPIPE_SZ`    | 调整管道缓冲区大小（Linux 特有）                 |

---

#### 6. 各命令详解

##### 6.1 复制文件描述符：`F_DUPFD`

- **作用**：查找大于或等于参数 `arg` 的最小且仍未使用的文件描述符，并复制 `fd` 指向的文件对象。
- **返回值**：成功返回新复制的文件描述符。
- **特性**：新描述符与 `fd` 共享同一文件表项（`struct file`），但拥有自己独立的文件描述符标志，其中 `FD_CLOEXEC` 标志被清除。
- **参考**：相当于 `dup(int oldfd)` 。

##### 6.2 获取/设置 close-on-exec 标志：`F_GETFD` / `F_SETFD`

- **`F_GETFD`**：取得 close-on-exec 标志。若 `FD_CLOEXEC` 位为 0，代表在调用 `exec()` 族函数时文件**不会**自动关闭。子进程会继承这个文件描述符，与父进程同时操作同一个文件。
- **`F_SETFD`**：设置 close-on-exec 标志，由参数 `arg` 的 `FD_CLOEXEC` 位决定。
- **典型场景**：管道、文件描述符在子进程中的继承控制。

##### 6.3 获取/设置文件状态标志：`F_GETFL` / `F_SETFL`

- **`F_GETFL`**（FL = Flags）：取得文件描述符状态标志，即 `open()` 时的 `flags` 参数。
- **`F_SETFL`**：设置文件描述符状态标志。参数 `arg` 为新标志，但**只允许修改 `O_APPEND`、`O_NONBLOCK` 和 `O_ASYNC`**，其他位（如读写模式）不受影响。

```c
int flags = fcntl(fd, F_GETFL);          // 获取当前标志
flags |= O_NONBLOCK;                     // 添加非阻塞标志
fcntl(fd, F_SETFL, flags);              // 设置新标志
```

##### 6.4 记录锁操作：`F_GETLK` / `F_SETLK` / `F_SETLKW`

- **`F_GETLK`**（LK = Lock）：检测文件锁定的状态。
- **`F_SETLK`**：设置文件锁定的状态。若无法建立锁定，立即返回 `-1`，`errno` 为 `EACCES` 或 `EAGAIN`。
- **`F_SETLKW`**（W = Wait）：与 `F_SETLK` 作用相同，但无法建立锁定时会**一直阻塞等待**，直到锁可用。若在等待过程中被信号中断，则立即返回 `-1`，`errno` 为 `EINTR`。

---

#### 7. 记录锁核心结构体 `struct flock`

```c
struct flock {
    short l_type;     // F_RDLCK(读锁), F_WRLCK(写锁), F_UNLCK(解锁)
    short l_whence;   // SEEK_SET, SEEK_CUR, SEEK_END (与 l_start 配合)
    off_t l_start;    // 起始偏移
    off_t l_len;      // 锁定长度（0 表示锁定到文件末尾）
    pid_t l_pid;      // 持有锁的进程ID（F_GETLK 时返回）
};
```

#### 记录锁示例：锁定文件的前 100 个字节

```c
struct flock lock;
lock.l_type = F_WRLCK;        // 写锁（独占）
lock.l_whence = SEEK_SET;     // 从头开始
lock.l_start = 0;             // 起始偏移 0
lock.l_len = 100;             // 锁定 100 字节（0~99）
lock.l_pid = 0;               // 调用时置 0

// 阻塞式加锁（等待直到成功）
if (fcntl(fd, F_SETLKW, &lock) == -1) {
    perror("加锁失败");
    exit(1);
}

// 操作文件区间...
read(fd, buf, 100);

// 解锁
lock.l_type = F_UNLCK;
fcntl(fd, F_SETLK, &lock);
```

#### 8. `fcntl` 记录锁 vs `flock` 对比

| 特性             | `flock`               | `fcntl` 记录锁                    |
| ---------------- | --------------------- | --------------------------------- |
| **锁粒度**       | 整个文件              | **可锁定文件的任意字节区间**      |
| **锁类型**       | 共享/独占             | 共享（读锁）/独占（写锁）         |
| **锁与 fd 关系** | 与 fd 表项绑定        | **与进程 + inode 绑定**（更稳定） |
| **锁继承**       | fork 继承，close 释放 | fork **不继承**，exec 可选继承    |
| **NFS 支持**     | 有限                  | **更好**（需挂载选项）            |

---

#### 9. 关键特性与注意事项

1. **锁的粒度是“字节区间”**：可以锁定文件的任意一段，如只锁第 100~200 字节，其他区域不受影响。这对数据库、索引文件等并发读写场景至关重要。

2. **锁与进程、inode 绑定**：
   - 同一进程多次对同一区间加锁，**后一次会覆盖前一次**。
   - **`fork()` 不继承**记录锁（子进程需重新加锁），与 `flock` 不同。
   - 进程退出时，所有记录锁自动释放。

3. **锁转换（升级/降级）**：可直接对已持有的锁区间再次调用 `F_SETLK` 改变类型。若冲突，`F_SETLK` 返回错误，`F_SETLKW` 阻塞等待。

4. **建议性锁**：与 `flock` 一样，`fcntl` 锁也是**建议性**的，不守规矩的进程依然可以直接读写。

5. **`fcntl` 与 `flock` 锁不互通**：两套独立的锁机制，互相感知不到对方。

---

#### 10. `fcntl` vs `flock` 选型建议

| 场景                               | 推荐           | 原因                                  |
| ---------------------------------- | -------------- | ------------------------------------- |
| 只需锁整个文件，逻辑简单           | `flock`        | 调用简单，代码清晰                    |
| 需要锁定文件部分区域（如数据库页） | `fcntl` 记录锁 | 精细控制，性能更好                    |
| 需要跨 NFS 网络文件系统            | `fcntl`        | NFS 对 `fcntl` 支持更好（需挂载选项） |
| 需要子进程独立加锁                 | `fcntl`        | fork 不继承，符合预期                 |

---

#### 11. 高级特性（快速了解）

- **`F_GETPIPE_SZ` / `F_SETPIPE_SZ`**：调整管道缓冲区大小（Linux 2.6.35+）。
- **`F_GET_SEAL` / `F_ADD_SEALS`**：文件密封（sealing），用于 memfd 和共享内存，防止文件被修改。
- **`F_OFD_GETLK` 等**：Open File Description（OFD）锁，Linux 3.15+ 引入，锁与打开文件描述（而非进程）绑定，行为更接近 `flock` 但支持区间锁定。
